# 竞品调研

> 客户与项目信息已脱敏处理。

面向 AI 产品落地的两项调研：一项看**行业产品怎么做**，一项看**Agent 接入企业 IM 后的权限风险**。前者为合同审核、制度审核两个落地项目提供产品思路与审核框架，后者为 Agent 的权限设计提供可执行的收敛方案。

## 调研方法

- **赛道分层**：按产品底层能力划分赛道，避免跨赛道乱比
- **流程拆解**：逐一还原头部产品的实际操作链路（上传 → 配置 → 审核 → 输出）
- **能力对标**：用横向对比表标定各产品的能力边界与空白点
- **规则溯源**：追溯审核依据来自法规库、判例库、实务规则还是企业内控
- **经验沉淀**：与历史审核类项目交叉验证

## 研究一：AI 合法合规审核竞品

覆盖 **5 大赛道、17 款主流产品**，从产品形态、审核流程到规则体系逐层拆解，最终收敛出行业通用的六层标准化能力架构：

```text
文档上传 → 结构化解析 → 场景策略配置 → 全维度风险扫描
        → 规则引擎校验 + 知识库溯源 → 风险分级聚合 → 标准化报告
```

核心结论：

- **审核维度已成体系**：合同 10 项（主体、标的、金额支付、履行期限、违约、保密、知识产权、争议解决、权责公平、程序合规），制度 6 项（合规、完整、一致、规范、可执行、时效）
- **规则分三级**：法定强制规则 → 行业惯例规则 → 企业内控规则，兼顾合规刚性与内控灵活性
- **知识库分四层**：权威法规库 + 司法判例库 + 行业实务库 + 企业私有库
- **交付统一为五合一**：风险总览、分级清单、原文批注、依据溯源、版本对比
- **人机分工清晰**：AI 做标准化、显性、规则化的筛查；商业合理性、复杂交易结构必须人工复核

完整逐页报告见 [`ai-compliance/report.html`](./ai-compliance/report.html)（自包含离线页面，浏览器直接打开）。

## 研究二：Agent 接入企业 IM 的权限风险

对比 4 款桌面端与 4 款云端 Agent 产品，从「能操作什么」「谁能控制」「操作是否二次确认」三个维度建立风险矩阵。

三条核心结论：

1. **能力同档，风险也同档**：主流桌面 Agent 都支持在企微群聊/私聊里操作本地文件，能力接近。
2. **控制权边界不清**：机器属于智能体部署者，但群聊里所有人都能发起控制，等于「多人可远程操作同一台部署者电脑」。
3. **云端更少兜底**：云端沙箱虽隔离了本机，但删除/覆盖普遍没有二次确认。

收敛建议：**Claw 端做高危操作询问与黑白名单，企微端按 userid 设主用户、其余只读**，两层同时生效。

详见 [`im-permission/README.md`](./im-permission/README.md)。

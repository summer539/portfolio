# Agent 接入企业 IM 的权限风险

> 客户与项目信息已脱敏处理。

## 调研问题

桌面端与云端 Agent 接入企业微信后，**谁能通过 IM 控制这台机器、能操作什么、误操作有没有兜底**？

## 对比矩阵

## 核心结论

1. **本地文件操作能力同档**：我方产品、WorkBuddy、QClaw 都支持通过企微群聊/私聊增删改本地文件；autoclaw 更收敛，只有客户端能改，删除需二次确认；JVS 本地侧不支持 IM 渠道。
2. **控制权限是最大风险点**：前三家机器控制权归智能体部署者，但群聊里所有人都能发起控制——相当于多人可远程操作同一台部署者电脑。autoclaw 的边界最清楚：只有创建者本人在客户端窗口能控制。
3. **待办能力存在盲区**：前三家只能看到机器人创建的待办，看不到用户自己创建的待办；autoclaw 能看到全部待办。
4. **云端不等于更安全**：虽然沙箱隔离了本机，但删除/覆盖普遍没有二次确认，误操作直接生效。

## 权限收敛建议

两层同时做，缺一不可：

**Claw 端（能力层）**

- 高危操作默认「询问」，支持按操作类型设置询问 / 总是允许 / 总是拒绝
- 对文件路径与命令做黑白名单
- 删除、覆盖等不可逆操作增加本地弹窗确认，而不是只在对话里提示

**企微端（身份层）**

- 设置唯一主用户，其余 userid 一律只读，禁止编辑与删除本地文件
- 必须用 userid 识别身份，不能依赖昵称
- 控制机器人可被谁 @、可管理哪些企微文档与待办

# 某陶瓷企业智能排产 — 路由器

## 职责

**不做具体排产计算，只做子技能调度和数据汇总。** 收到排产请求后按阶段串行/并行执行。

## 顶层认知

**营销计划表的唯一作用：告诉AI"哪些产品需要排产"（产品清单）。**

```
营销计划表 → 产品清单（决定排哪些产品）
     ↓
  AI拿着清单去ERP查库存/销量 → 跑V6算法 → 产出AI排产建议
     ↓
  并排输出（AI建议 vs 营销建议对照展示，互不影响）
```

- plan_qty 仅用于Excel中与AI建议并排对照，不参与算法计算
- 无营销计划表时，唯一缺的是产品清单（可通过库存告急筛选等方式补充）

## 子技能清单

| 子技能 | 路径 | 职责 | 输入 | 输出 |
|--------|------|------|------|------|
| data-fetch | `sub-skills/data-fetch/` | Excel解析 + ERP三路查询 | Excel文件路径 | `/tmp/schedule-data.json` |
| schedule-a | `sub-skills/schedule-a/` | 某陶瓷企业规则校核 + V6裁决 | data.json | `/tmp/schedule-a-result.json` |
| schedule-b | `sub-skills/schedule-b/` | B 基地规则校核 + V6裁决 | data.json | `/tmp/schedule-b-result.json` |
| export-excel | `sub-skills/export-excel/` | Excel输出 | a-result.json + b-result.json | xlsx文件路径 |

## 执行流程

### 阶段0：意图确认（前置判断，避免空跑）

收到排产请求后，**必须先确认排产范围**，再决定调度哪些子技能。

若用户已明确说明排产范围（如"仅某陶瓷企业"、"B 基地无需排产"、"两个基地都排"），则直接进入阶段1，无需反复询问。

若排产范围不明确，向用户确认：

> 请确认本次排产范围：
> **A.** 仅A 基地
> **B.** 仅B 基地
> **C.** 某陶瓷企业 + B 基地 双基地同时排产

根据用户回答（或已明确的意图），设置排产范围标识。

### 阶段1：数据拉取（串行，必须等完成）

```
sessions_spawn → data-fetch
  消息: "数据拉取 | 文件: {Excel绝对路径} | 排产日期: {YYYY-MM-DD} | 排产范围: {仅某陶瓷企业/仅B 基地/双基地}"
  等待完成 → 验证 /tmp/schedule-data.json 存在
```

**从返回中提取并打印数据源概览：**
- 文件标题、规格、窑炉参数
- 品牌数/产品数/定制/新品/营销总排产
- ERP匹配率、库存覆盖数、出库记录数

### 阶段2：排产裁决（根据阶段0意图有选择地启动）

```
仅某陶瓷企业 → sessions_spawn schedule-a
仅B 基地   → sessions_spawn schedule-b
双基地   → sessions_spawn schedule-a + schedule-b（并行）

消息格式:
  schedule-a: "某陶瓷企业排产 | 数据: /tmp/schedule-data.json"
  schedule-b:  "B 基地排产 | 数据: /tmp/schedule-data.json"

sessions_yield → 等待启动的子技能全部完成
```

**从返回中汇总打印：**
- 某陶瓷企业（如有）：违规统计 + Top3计算链路 + AI总排产
- B 基地（如有）：违规统计 + Top3计算链路 + AI总排产

### 阶段3：输出（根据排产范围选择脚本）

```
单基地 → sessions_spawn export-excel（单基地模板）
  消息: "单基地输出 | 基地: {某陶瓷企业/B 基地} | 结果: /tmp/schedule-{a/b}-result.json"
  脚本: sub-skills/export-excel/scripts/generate_excel_single.py

双基地 → sessions_spawn export-excel（双基地模板，原流程不变）
  消息: "合并输出 | a: /tmp/schedule-a-result.json | b: /tmp/schedule-b-result.json"
  脚本: sub-skills/export-excel/scripts/generate_excel.py
```

**输出最终Excel文件路径。**

## 输出规范

最终完成后打印四段报告：

### 1. 数据源说明

| 数据 | ERP覆盖 | 原因 |
|------|---------|------|
| 库存 | X/Y | 成品一仓(某陶瓷企业)+成品三仓(B 基地) |
| 销量 | X/Y | SAL_OUTSTOCK(某陶瓷企业100080+B 基地100082)，排除某销售中心 |

### 2. 核心结果

```
规格: X×X | X号窑 | X片/箱 | 日产X箱
营销X箱 → AI X箱 (±X%)
某陶瓷企业产能利用率X% | B 基地产能利用率X%
```

### 3. 关键异常（从两基地合并）

| 类型 | 数量 | 重点 |
|------|------|------|
| 🚨库存告急 | X项 | 产品及问题 |
| ⛔库存积压 | X项 | 产品及库存量 |

### 4. 文件路径

所有产出文件统一放在工作空间的 `产出文件/` 目录下：

```
{workspace}/产出文件/对标X月X日-规格-智能排产优化方案-YYYYMMDD.xlsx
```

## 🔴 铁律

1. **阶段1串行**：data-fetch 必须等完成才能进入阶段2
2. **阶段2并行**：schedule-a 和 schedule-b 同时启动
3. **阶段3串行**：export-excel 等阶段2两者都完成才启动
4. **数据仅通过临时JSON文件传递**，不在消息体中夹带大量数据
5. **每个子技能失败都要报错**，不静默跳过
6. **最终必须输出 Excel 文件路径**，这是用户唯一关心的交付物
7. **子技能超时不等于失败**：先检查输出JSON是否已写入，如已写入则直接进入下一阶段
8. **export-excel 必须执行固化脚本**：`python3 sub-skills/export-excel/scripts/generate_excel.py`，严禁自行写代码生成Excel

## ⚠️ 已知陷阱（每次执行前必须检查）

| 陷阱 | 现象 | 检查方式 |
|------|------|----------|
| base字段缺失 | schedule-b找不到产品 | `grep '"base"' data.json \| grep null \| wc -l` |
| JL产品库存来自错误仓库 | B 基地库存≠0但实际应为0 | 验证JL产品的erp_stock是否来自177653 |
| B 基地营销数据污染 | B 基地plan_qty≠0 | 确认B 基地是否真有独立营销计划表 |
| d90日均误读为总量 | 工作人员困惑 | 确保列名标注"日均" |
| data-fetch超时但文件已写 | 误判为失败 | 不重新执行，直接验证文件 |
| export-excel自创格式 | 输出不是16列品牌区块格式 | 阶段3必须执行固化脚本，不得自行写代码 |
| 图片不可见 | ext cx=0/cy=0 | 固化脚本已修复（OneCellAnchor+ext+PIL预缩放） |
| 底标文字被图片遮盖 | 文字不可读 | 固化脚本已修复（top_margin+vertical=top） |

## 🖊️ 展示规范（所有子技能遵守）

### 0. Excel列结构（16列，固化脚本保证）

品牌|上线时间|生产编号|备注|计划库存(箱)|实时库存(箱)|营销排产|AI排产|近7天日均销量|近30天日均销量|近90天日均销量|底标|厚度|纸箱(图片)|趋势|AI备注|

Sheet3 汇总总览为22列（追加序号\|基地\|规格\|工艺\|6月\|7月\|优先级\|vs营销\|vs人工等维度）。

### 1. 销量数据标注

**所有输出中的 d7/d30/d90 均为日均销量**（总销量÷天数），不是总量。Excel列名使用"近7天日均销量""近30天日均销量""近90天日均销量"。

### 2. 双库存列区分

Excel排产结果必须包含两个库存列：
- **计划库存(箱)**：来自营销计划表Excel中的库存数（可能滞后）
- **实时库存(箱)**：来自ERP成品仓的实时库存（权威数据源），<500箱标红高亮

排产计算以ERP实时库存为准，但两个数据都展示供核对。

### 3. AI备注通俗化

AI备注必须用中文日常语言，让产线工作人员能直接理解排产逻辑：
- ✅ "库存告急（实时库存207箱），近30天日均出库455箱，趋势波动，建议排产2500箱"
- ❌ "gap_7=5317, d_weighted=395, effective_gap取大 → P=5500"
- 禁止写"可撑999天"等超长天数，>90天统一写"库存积压"

### 4. 库存天数展示

- 库存天数<30天：展示具体天数（可撑X天）
- 库存天数≥30天：写"库存充足"即可
- 日均=0（无近期出库）：写"近期无出库"
- 禁止显示"428天""999天"等超长数字

# 智能排产技能包

> 客户为某陶瓷制造企业，项目信息已脱敏处理。

这个技能包由两个相互独立的技能组成：**智能排产**（`prod-schedule`）负责按营销计划表产出排产方案，**每日经营日报**（`daily-report`）负责产销率与回款率的自动播报。两者共用同一套 ERP 取数底座，但不共享代码。

## 一、智能排产（prod-schedule）

### 顶层设计：营销计划表只提供「产品清单」

这是整个技能最关键的认知：营销计划表的作用不是给数量，而是告诉 AI **哪些产品需要排产**。数量由 AI 拿着清单去 ERP 查库存与销量后自己算，最后与营销建议并排对照展示，互不影响。

```text
营销计划表 ──▶ 产品清单（排哪些产品）
                  │
                  ▼
        ERP 查库存 / 销量 ──▶ V6 裁决算法 ──▶ AI 排产建议
                  │
                  ▼
        与营销建议并排输出（对照，不互相覆盖）
```

### 路由器 + 子技能架构

主技能不做具体计算，只负责调度：

| 子技能 | 职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| `data-fetch` | 解析计划表 + ERP 三路查询（物料→库存→销量） | Excel 路径 | `/tmp/schedule-data.json` |
| `schedule-a` | A 基地规则校核 + V6 裁决 | data.json | `/tmp/schedule-a-result.json` |
| `schedule-b` | B 基地规则校核 + V6 裁决 | data.json | `/tmp/schedule-b-result.json` |
| `export-excel` | 按单/双基地生成排产 Excel | 结果 JSON | xlsx |

执行分五个阶段：意图确认（先问清排产范围，避免空跑）→ 数据拉取（串行）→ 两个基地的排产裁决（并行）→ 结果合并 → Excel 输出。

### 裁决算法

`scripts/ruling_engine.py` 是排产建议的决策核心，按多时间维度做缺口裁决，包含三日均与趋势判定（加速上涨／回暖上涨／脉冲波动／持续衰减／骤降／平稳等）、双缺口计算、趋势加成、安全阀与优先级排序，并输出风险标记。

### 规则与数据资产

- `references/logic-design.md` — 整体逻辑方案：数据预处理 → 规则校核 → 智能优化建议 → 方案输出，附可配置参数表
- `references/rules.md` — 排产规则参数表
- `references/erp-catalog.md` — 金蝶 ERP 数据资产清单：组织架构、可用仓库、数据表与字段清单、哪些模块不可用
- `references/output-format-design.md` — 输出模板设计（品牌、工艺、纸箱与底标图片的排布）

## 二、每日经营日报（daily-report）

每天三个定时任务，串成一条闭环：

```text
23:59  库存快照    STK_Inventory  ──▶ data/snapshots/{date}.csv
08:30  邮箱日报    SAL_OUTSTOCK + AR_RECEIVEBILL ──▶ HTML 日报 + CSV 附件
09:00  企微晨报    同上 + 昨日/前日快照 ──▶ 文本晨报
```

核心指标有四个：**产销率**（用库存快照反推产量，而不是依赖生产订单模块）、**月累计回款率**、**断货／积压预警**、**TOP5 畅销产品**。计算口径单独写在 `references/calculation_rules.md` 里，与代码分离。

## 三、这套技能里最值得看的部分

### ERP 取数的坑，全部写成了规则

金蝶云星空的数据模型和直觉不一样，技能里逐条固化了纠错记录：

- 排产表里的物料编码要匹配 ERP 的 `FName`（物料名称），**不是** `FNumber`（系统编码），匹配错了整表查不到；带 `-HB` 后缀的编码查不到时要回退去掉后缀重试
- 销量字段要用 `FRealQty`（实际出库数量）而不是 `FQty`；赠品由 `FIsFree` 标识，金额恒为 0 但计入出库量，需单独标注
- 收款单必须带上单据号 `FBillNo` 才会按分录行返回，否则行级金额会重复整单金额
- 库存要按产品聚合后再统计，首次查询返回的多批次明细行（数千行）不是产品级数据

### 业务口径来自客户确认，且标注确认日期

等级口径（优等品 = 优等 + 优AA）、统计组织范围、只统计成品仓、内部关联客户整单排除——这些都写成了代码常量并附上客户确认日期。口径改动必须人工确认，不允许模型自行调整。

### 两个技能各自独立

排产与日报是两个技能、两套脚本，只共享 ERP 连接方式。这样任一技能改动都不会互相影响，也可以分别部署给不同角色使用。

## 目录结构

```text
skill-pack/
├── prod-schedule/                     # 智能排产（路由器）
│   ├── SKILL.md
│   ├── sub-skills/
│   │   ├── data-fetch/SKILL.md
│   │   ├── schedule-a/SKILL.md
│   │   ├── schedule-b/SKILL.md
│   │   └── export-excel/{SKILL.md, scripts/generate_excel*.py}
│   ├── references/                    # 逻辑方案、规则参数、ERP 资产清单、输出格式
│   └── scripts/                       # 裁决引擎、ERP 取数、结果导出、环境检测、配置模板
└── daily-report/                      # 每日经营日报
    ├── SKILL.md
    ├── references/                    # 部署说明、计算口径、ERP 配置
    ├── scripts/                       # 快照、邮箱日报、企微晨报、ERP 查询
    └── templates/                     # 邮件、企微、附件模板
```

## 运行依赖

- Python 3.10+；`kingdee.cdp.webapi.sdk`（金蝶云星空 WebAPI）、`openpyxl`、`pandas`
- 定时任务通过平台的 cron 能力注册（`openclaw cron add`），不使用系统 crontab
- 企业微信消息通过平台的消息通道发送

## 未包含的内容与脱敏说明

**凭证已全部替换为占位符。** 原始技能包中硬编码了生产环境的对接信息，以下内容一律未入库：

- 金蝶 ERP 服务器地址、账套 ID、应用 ID 与**应用密钥**
- 用于发送日报的企业邮箱账号与**邮箱授权码**
- 企业微信的账号与目标 ID

> 提醒：这些凭证原样放在技能包文件里，凡是拿到过这个压缩包的人都能看到。建议尽快在 ERP 侧重置应用密钥、并更换邮箱授权码。

其他未纳入仓库的内容：

- 品牌素材库（约 1,670 个文件、75 MB）：按窑炉／规格／工艺／品牌组织的纸箱与底标图片及编号索引，属于客户产品资料
- 每日库存快照 CSV、日报 HTML、回款分析、排产方案 xlsx 等产出文件：均为真实经营数据
- 智能体的逐日工作日志（`memory/`、`MEMORY.md`）：含真实库存、销量、销售额与回款数据
- 根目录下的一次性探查脚本与原始查询结果 JSON

脱敏处理：客户名称替换为「某陶瓷制造企业」，两个生产基地替换为「A 基地」「B 基地」，其他分公司／基地替换为「某分公司」，涉及的业务员姓名与代工品牌名替换为通用描述，代码中的绝对路径与工作区路径改为相对路径。

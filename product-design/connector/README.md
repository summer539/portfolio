# 连接器产品设计：用户流程与页面原型

> 项目信息已脱敏处理。

## 背景

Claworks 桌面端要接入外部工具（MCP 连接器）。原来的问题不是「能不能连」，而是用户从哪进、连上之后怎么用、失败之后怎么办——这些路径不梳理清楚，原型就只能做出一堆孤立的弹窗。

我配合产品经理，把连接器从入口到解绑的全过程画成一张流程图，再按图落成可点击的高保真原型。

## 设计范围

### 三条入口路径

| 路径 | 适用场景 |
| --- | --- |
| 侧边栏【连接器】 | 用户主动管理连接器 |
| 新建对话 → 侧边栏【连接器】 | 已经在新任务里，顺手添加 |
| 新建对话 → 输入框【连接】→【管理连接器】 | 写任务时发现缺工具，就地解决 |

### 两种添加方式

- **内置连接器**：浏览 / 搜索卡片 → 连接。支持「点击卡片看详情」和「卡片右侧【+】快速连接」两条路，后者省掉详情页。
- **自定义连接器**：打开配置弹窗 → 配置 MCP → 输入连接器信息 → 即时校验 → 保存 → **开启信任** → 添加成功。

### 三种授权结果

第三方是否支持内嵌，决定走页面内嵌还是跳转浏览器；授权结果不只「成功」一种：

| 结果 | 系统反馈 |
| --- | --- |
| 授权成功 | 轻提示「连接器添加成功」，回到连接器页面 |
| 3 分钟未操作 | 轻提示「连接失败超时」，可重试 |
| 用户手动取消 | 轻提示「已取消授权」，回到连接器页面 |

### 四类后续操作

- **对话**：点击卡片、详情页、新建任务、连接器菜单都能进入；支持选择示例提示词、使用默认示例或手动输入，再选择智能体发送
- **关闭连接**：保留配置，仅断开当前会话
- **删除连接**：移除连接器配置
- **解除绑定**：从已连接的卡片进入，解除后回到未连接状态

## 关键设计判断

1. **入口不做单点**：连接器既可能被主动管理，也可能在任务中被临时需要，所以保留三条入口，而不是只放一个设置页。
2. **内置连接器走最短路径**：卡片【+】直达配置，详情页只服务「我需要先了解它能干什么」的用户。
3. **自定义连接器加一道「信任」**：MCP 配置完成后不默认授权，要求用户显式开启信任，避免误连未知服务。
4. **授权状态要穷举**：成功、超时、取消三种结果都要有明确反馈，否则用户会卡在「到底连上没有」。
5. **生命周期动作分开**：关闭、删除、解绑不是一回事，UI 上分别对应不同入口和文案，避免误操作。
6. **对话入口多样化**：从卡片、详情、新建任务、菜单都能发起对话，减少用户回退成本。

## 演示建议

1. 打开 `prototype/index-standalone.html`
2. 从侧边栏进入【连接器】，分别走一遍内置连接器与自定义连接器
3. 在连接配置弹窗里点「模拟超时」，演示授权超时后的反馈
4. 回到对话，点击输入框左侧【连接】，演示「任务中就地添加」的路径

# 输出数据契约

## 1. 输出目录

脚本执行后在指定目录生成：

```text
<output-dir>/
├── 一致性快速审核报告.md
└── 一致性快速审核汇总.json
```

逐项审核时可另增：

```text
<output-dir>/
├── 一致性审核报告.md        （逐项审核报告）
└── 一致性审核汇总.json      （逐项审核汇总）
```

同一输出目录中的固定文件名会被覆盖。批量或并发任务必须使用不同输出目录。

## 2. 汇总 JSON

`一致性快速审核汇总.json` 是系统集成的主入口：

```json
{
  "audit_info": {
    "parsed_at": "ISO-8601 时间",
    "elapsed_seconds": 0.0,
    "documents": [{"file_name": "", "title": ""}],
    "total_conflicts": 0,
    "hard_conflicts": 0,
    "soft_inconsistencies": 0
  },
  "internal_conflicts": [],
  "cross_conflicts": []
}
```

## 3. 冲突对象结构

每个冲突项包含以下字段：

| 字段 | 含义 |
|---|---|
| `id` | 冲突编号，内部冲突以 `IC-` 前缀，跨制度冲突以 `XC-` 前缀 |
| `topic` | 冲突点简述 |
| `dimension` | 维度代码 A-H |
| `type` | 冲突类型：硬冲突 / 软不一致 / 待确认 |
| `severity` | 严重度：高 / 中 / 低 |
| `evidence` | 证据数组，每条含 `document`（文件名）、`location`（位置）、`excerpt`（原文摘录） |
| `suggestion` | 修改建议 |

证据至少 2 条（双方或多方），内部冲突的 `document` 字段可省略（单文档场景）。

## 4. 冲突类型

| 类型 | 含义 | 系统处理建议 |
|---|---|---|
| `硬冲突` | 同一事项规定直接矛盾 | 必须处理，否则导致执行歧义 |
| `软不一致` | 定义/口径/表述不统一但未直接矛盾 | 建议处理，影响体系协调性 |
| `待确认` | 证据不足或语义模糊 | 转用户确认，不入冲突统计 |

## 5. 严重度

| 严重度 | 含义 | 定级依据 |
|---|---|---|
| `高` | 硬冲突，或可能导致执行歧义/合规风险/责任真空 | 同一事项直接矛盾；权限互斥；标准数值不同 |
| `中` | 软不一致，口径不统一但不直接矛盾 | 定义口径不同但可兼容；称谓不一；裁量基准未统一 |
| `低` | 纯表述差异，不影响执行效力 | 同义替换；标点差异；排列顺序差异 |

## 6. 术语一致性矩阵

模式一必填，模式二可只列修订条款涉及的术语。每条结构：

```json
{
  "term": "术语名",
  "definitions": [
    {"document": "文件名", "article": "条款号", "definition": "定义文本", "abbreviation": "简称"}
  ],
  "consistent": true,
  "note": "说明"
}
```

## 7. 维度代码

| 代码 | 名称 |
|---|---|
| A | 关键术语定义统一性 |
| B | 处罚标准一致性 |
| C | 审批流程一致性 |
| D | 职责主体一致性 |
| E | 程序参数一致性 |
| F | 数额比例期限一致性 |
| G | 引用法规一致性 |
| H | 适用范围一致性 |

## 8. 版本兼容

- 下游系统应优先按字段名解析，不依赖数组顺序或 Markdown 文案。
- 新增审核维度时使用新字母编号，保持既有维度含义不变。
- 脚本提取的关键信息模式（费率、阈值等）可能随制度类型扩展，新增模式不影响已有字段。

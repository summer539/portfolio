# 不同制度类型必备条款清单（审核规则基线）

> 版本：V1.0  
> 校验日期：2026年8月27日  
> 配套文件：《制度起草指引要求》  
> 用途：按制度业务类型匹配内容完整性审核点，检查是否遗漏法定要求、监管要求、企业内控要求或关键业务闭环。  
> 提示：本清单不直接替代法律意见。正式部署前，应由公司法务和相应业务部门核验法律依据、适用条件及内部授权体系。

## 一、清单使用规则

### 1. 要求来源等级

| 代码 | 来源等级 | 含义 | 缺失处理 |
|---|---|---|---|
| A | 法律法规或监管强制 | 满足适用条件时，法律法规或监管规范明确要求建立制度、机制或作出规定 | 原则上高风险，必要时转法务复核 |
| B | 企业治理或内控必备 | 为形成完整管理闭环通常必须具备 | 原则上中高风险 |
| C | 推荐完善 | 有助于提升可执行性、可追溯性和风险控制 | 低风险或优化建议 |

### 2. 适用判断

1. 先识别制度主类型和副类型；
2. 主类型规则正常适用，副类型规则在确有交叉业务时叠加；
3. 不得仅因名称包含关键词，就机械适用该类型全部规则；
4. 应结合调整对象、适用主体、业务流程和管理事项判断；
5. 法定规则必须同时满足其适用条件；
6. 不满足条件的，输出“不适用”及理由，不得省略；
7. 类型无法识别时，执行通用规则，类型化规则标记“待确认”。

### 3. 内容状态

| 状态 | 判定标准 |
|---|---|
| 通过 | 明确覆盖主要内容要素，并能提供原文证据 |
| 部分通过 | 提及相关事项，但主体、条件、标准、程序、时限或责任不完整 |
| 不通过 | 制度应当规定但未发现相关内容 |
| 待确认 | 存在疑似规定、引用外部文件或材料不足，无法可靠判断 |
| 不适用 | 经适用条件判断，该条款不适用于本制度 |

# 十七、机器化规则字段建议

每个必备条款转换为代码规则时，建议至少包含：

| 字段 | 说明 |
|---|---|
| id | 唯一、稳定的审核点编号 |
| category | mandatory_clause |
| policy_types | 适用制度主类型和副类型 |
| source_level | A、B或C |
| applies_when | 适用条件和排除条件 |
| required_aspects | 必须覆盖的实质要素 |
| heading_aliases | 可接受的章节标题别名 |
| keywords | 检索召回词，不直接等同于通过 |
| semantic_review | 是否需要语义复核 |
| evidence_required | 是否必须返回原文证据 |
| severity | 缺失和部分缺失的严重程度 |
| legal_basis | 依据文件、条款、版本和生效日期 |
| suggestion_template | 缺失后的补充方向 |

执行器应强制遍历所有经适用性筛选后的规则，并输出规则覆盖率。未执行规则、重复结果及缺少证据的“通过”结论，均应作为运行异常处理。

# 十八、维护要求

1. 法律法规、监管规定或公司制度变化时，更新对应规则依据、适用条件和版本；
2. 不得只因关键词命中就判定完整，应核对主体、条件、程序、标准、时限和责任；
3. 未命中关键词但存在语义等价内容时，应进行语义复核；
4. 法定条款缺失或适用性有争议时，应进入法务复核；
5. 企业自定义规则应标明制度来源、发布部门、版本和生效日期；
6. 同一制度可匹配多个类型，系统应保留主类型和副类型选择记录；
7. 本清单检查“是否规定及是否基本完整”，不直接判断条款最终是否合法、有效或与其他制度一致。

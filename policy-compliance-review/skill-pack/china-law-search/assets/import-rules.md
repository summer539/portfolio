# 入库规范（Import Rules）

把法规采集入库到本地 SQLite 库（`law.db`：laws / articles / articles_fts 三表，FTS5 trigram 全文索引）的标准流程与字段约定。
**所有逻辑已固化在 `scripts/lawdb_import.py`，直接复用，无需重写脚本。**

## 一、标准流程（必须遵守）

1. **两库预检**：先查 flk + 国家规章库（`law_search.unified_batch_check`）
   - 查到的：可下载官方 docx/pdf 后用 `lawdb/build_lawdb.py` 导入（走 docx 解析）
   - **查不到的**（党内法规、通知/意见/指引等规范性文件）：走官方网抓取（本导入器）
2. **找权威官方源**：按 `data-source-rules.md` 的白名单渠道，避免商业转载站
3. **入库**：`import_law_from_url` 或批量 `import_batch`（幂等：同名同 level 先删旧再插）
4. **验证**：条文编号连续性 + 章节字段非空 + 无页面噪音残留（脚本已验证，重跑即得）

## 二、入库字段约定

| 字段 | 约定 |
|---|---|
| `level` | 法律 / 行政法规 / 部门规章 / 规范性文件 / 党内法规 / 香港法规 等 |
| `status` | 默认"现行有效"；修订/废止需核实后标注 |
| `source` | 数据来源标识（如"官方网站"、"香港交易所"） |
| `official_url` | 官方来源 URL，**必须记录**，汇报时列出 |
| `doc_no` | 文号（可空） |
| `preamble` | 题注/审议批准信息（可空） |
| `effective_date` | 施行日期 |

## 三、解析规则

- 自动判定解析模式：
  - 含"第X章/第X条" → 标准式 `parse_standard`
  - 条目式（一、二、三…每块一条）→ `parse_item`
- 条文编号用**文本编号**（第一百五十八条 → 158），不是顺序号
- 章节入库为 `(序号, 章节名)` 元组列表格式（与 docx 导入一致）；articles 的 chapter 字段传序号
- 指引/守则类无"第X条"结构的文件：按一级标题切块成条文，遇"附件"截断，引言并入第一块
- 香港守则类（附录 C1/C3）：字母章节（A./B./C./D.）+ 预定义章节词表，条文编号保留原文（A.1.1 等）

## 四、文件命名规则

下载文件命名: `法规类型_法规名称_公布日期_状态.ext`

```
法律_中华人民共和国安全生产法_2021-06-10_有效.docx
```

## 五、幂等与重导

- 重复导入同名同 level 法规前先删旧（`import_law_from_html` 已内置）
- 数据质量问题（条数缺失/噪声）修复后：删旧记录 → 重新导入，保证可复现
- 批量导入建议 `delay=2` 秒防封

## 六、模板

- 批量导入 JSON 清单模板：`references/batch-entries.example.json`
- 查询结果格式与转换模板：`references/output-format.md`
- 进度文件结构：`references/progress-files.example.md`

## 七、数据源时效性

- 入库前确认现行版本（如《党政机关厉行节约反对浪费条例》2025-05-02 已修订为 11 章 63 条）
- 党内法规注意修订版本与施行日期（如纪律处分条例 2023 修订版 158 条，2024-01-01 施行）
- 多版本法规明确标注版本与日期，避免新旧混淆

## 八、status 三级判定（JSON 无时效性字段时，2026-08-28 定稿）

当批量 JSON 未提供"时效性"字段（如 flk 结构化提取 8zip 版）时，按以下顺序判定 status，**不得直接全部标"现行有效"**：

1. **旧版本识别**：同标题存在更新版本（库内 + JSON 内取最大公布日期）→ 旧版标 `已修改`
2. **废止决定交叉核对**：解析国务院《关于（修改和）废止部分行政法规的决定》的**附件2/正文废止清单**，命中 → 标 `已废止`（附废止依据决定日期）
   - ⚠️ 已知坑：flk 结构化 JSON 的 full_text **不含附件2 表格**（docx 表格解析丢失），废止清单需从 flk 重新下载决定 docx 解析（`python-docx` 读 tables + "附件2"后段落）
   - 清单格式两种：`废止《XXX》` 或 `一、XXX（YYYY年M月D日…公布/发布）`；名称匹配需规范化（去"中华人民共和国"前缀、书名号、空白）
   - 已归档废止清单（7 份决定 33 项）见 `assets/abolition-lists.md`（2021-09-09/2022-03-29/2023-02-14/2024-03-10/2024-12-06/2026-01-30/2026-08-08）
3. **施行日期核实**：`flk_api.search` 返回 `sxrq` 字段，`sxrq > 今天` → 标 `尚未生效`；同时把核实的 sxrq 回填 `effective_date`（JSON 题注提取经常缺失）
   - 反爬提醒：单次核实 ≤ 40 请求，间隔 ≥ 1.5s；超时报错单条重试即可

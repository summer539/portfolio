# 制度审核文档批注结构规范

> 本规范面向生成修订文档的 AI 智能体。遵循以下规则产出的 .docx 文件，
> 可被阅读器可视化 demo 精准解析，无需复杂文本匹配逻辑。

---

## 1. 核心原则

批注（comment）与修订（tracked change）的关系通过 **XML 位置** 隐式表达，
不依赖文本内容匹配。具体来说：

- commentRangeStart 必须放在它所标注的**第一个修订元素之前**（同段落、同级）
- commentRangeEnd 必须放在它所标注的**最后一个修订元素之后**
- 阅读器通过遍历 XML 树，追踪 commentRangeStart 到 commentRangeEnd 之间的
  活跃批注集合，遇到 ins/del 元素时快照，从而精确知道每条修订属于哪个批注

## 2. 修订类型

| 类型 | OOXML 元素 | 含义 |
|------|-----------|------|
| 新增 | w:ins | 插入新文本，含 w:t 子元素 |
| 删除 | w:del | 删除旧文本，含 w:delText 子元素 |
| 修改 | w:del + w:ins 相邻 | 先删后增或先增后删，视为同一次替换 |

## 3. 批注结构规则

### 3.1 修改类（删除 + 新增）

一条批注对应一次修改（既有删除又有新增）时，commentRangeStart 包到 del 之前，
commentRangeEnd 包到 ins 之后：

```xml
<w:p>
  <w:commentRangeStart w:id="1001"/>
  <w:del w:id="1" w:author="AI" w:date="2026-01-01T00:00:00Z">
    <w:r><w:delText>旧文本</w:delText></w:r>
  </w:del>
  <w:ins w:id="2" w:author="AI" w:date="2026-01-01T00:00:00Z">
    <w:r><w:t>新文本</w:t></w:r>
  </w:ins>
  <w:commentRangeEnd w:id="1001"/>
  <w:r><w:rPr><w:rStyle w:val="CommentReference"/></w:rPr>
    <w:commentReference w:id="1001"/></w:r>
</w:p>
```

### 3.2 纯新增类

只有新增没有删除时，commentRangeStart/End 包住 w:ins：

```xml
<w:commentRangeStart w:id="1002"/>
<w:ins w:id="3" w:author="AI" w:date="2026-01-01T00:00:00Z">
  <w:r><w:t>新增内容</w:t></w:r>
</w:ins>
<w:commentRangeEnd w:id="1002"/>
```

### 3.3 纯删除类

只有删除没有新增时，commentRangeStart/End 包住 w:del：

```xml
<w:commentRangeStart w:id="1003"/>
<w:del w:id="4" w:author="AI" w:date="2026-01-01T00:00:00Z">
  <w:r><w:delText>被删除的文本</w:delText></w:r>
</w:del>
<w:commentRangeEnd w:id="1003"/>
```

## 4. ID 规则

- 所有 w:ins/w:del 的 w:id 必须是**全局唯一**的正整数
- 所有 w:comment 的 w:id 必须是**全局唯一**的正整数
- 修订 ID 和批注 ID 使用不同的数字空间，互不冲突
- 阅读器在加载时会自动重排修订 ID，但批注 ID 保持原值

## 5. 批注文本规范

批注是"给人看的"，要求**可读、有说服力**。每条批注为强制**四段式**，**四段之间用真换行（\n）分隔**（脚本自动转为 w:br；禁止用 `｜`、空格或逗号分隔）：

1. **【修改】**（标签随修订性质变化：【修改】/【新增】/【删除】）：一句话"问题 + 怎么办"（如 `引用过时/错误依据，招标代理机构资格认定已取消，应修改该表述`）。**不写条款位置、不带"类型X"编号** —— 位置由 commentRange 锚点承担。
2. **【修订依据】**：人话转述。先概括正确做法方向，再"依据《法规名称》第X条：核心要义一两句（不抄原文）+ 对制度的要求或后果"；涉及废止的标注"（已废止）"。**不含 article_id**（可追溯性由修订清单/数据文件承担）。
3. **【修订建议】**：可直接落地的修改文本（删除"……"、修改为"……"）。
4. **【修订性质】**：**结构化信息（供前端解析展示，非阅读用途）**，第一行=性质枚举（修改/新增/删除），其后为 `{键}：值` 行，前端按行解析：
   - 修改：`修改` / `{原始}：<最小修订范围完整原文>` / `{修改}：<完整修改后表述>`
   - 新增：`新增` / `{新增}：<新增内容>`
   - 删除：`删除` / `{删除}：<被删内容完整原文>`
   - 旧数据缺 `revision_type` 时回退 `修改` 且无 {原始}/{修改} 行

示例（换行分隔，四段）：

> 【修改】未按法定指定媒介发布公告，应改按法定指定媒介发布并同步电子平台
>
> 【修订依据】依据《中华人民共和国招标投标法》第十六条和《招标投标法实施条例》第十五条，依法必须招标项目的资格预审公告、招标公告应当在国务院发展改革部门依法指定的媒介发布，且不同媒介发布的同一项目公告内容应当一致；《电子招标投标办法》第十七条还要求在电子招标投标交易平台同步发布。公告发布媒介属法定事项，代理机构无权自行选择，制度"由代理机构根据项目情况自行选择、可在公司内部网站发布"不符合法定发布渠道要求。
>
> 【修订建议】修改为："依法必须进行招标项目的资格预审公告和招标公告，应当在国务院发展改革部门依法指定的媒介发布……"
>
> 【修订性质】修改
> {原始}：公告发布媒介由采购代理机构根据项目情况自行选择,可在公司内部网站或代理机构网站发布
> {修改}：依法必须进行招标项目的资格预审公告和招标公告，应当在国务院发展改革部门依法指定的媒介发布，并按电子招投标要求在电子招标投标交易平台同步发布

### 已知坑（务必遵守）

- **坑 ① 换行不生效**：`docx_comments` 的 `add_comment` 把整段文本塞进单个 `w:t`，`\n` 不会显示为换行。`revision_edit.py` 已内置 `_split_comment_newlines(mgr, cid)`（按 w:id 找到 comment，把 `w:t` 按 `\n` 拆为 `w:t + w:br + w:t` 序列，再 `_save_comments()`），三个批注入口（anchored / multi / to_para）均已接入。**不要绕过该函数**；手工写 comments.xml 时须自行用 `w:br` 分段。
- **坑 ② 去 article_id 留空括号**：批注文本清理 `（article_id=XXXX）` 后必须清理残留空括号 `（）`（`while "（）" in s: s = s.replace("（）", "")`）。嵌套场景 `（文号，article_id=…，现行有效）` 先删 `[,，]?\s*article_id=\d+(?:/\d+)*` 片段（保留"现行有效"），再兜底删整括号、清空括号。

## 6. 禁止事项

- **禁止**将 commentRangeStart 放在 w:ins 或 w:del 元素内部
  （必须放在同级，作为段落的直接子元素）
- **默认逐条批注，禁止合并**：一个清单条目（item）= 一条批注，精确锚定该条目自己的修订处；同一条款下的多个子项（如第八条第（六）（九）（十三）项）**必须各自独立成批注**，不得合并，也不得把整条条款整体做批注（2026-09-01 用户明确）。
- **跨段合并批注**（仅 items.json 顶层 `"merge_by_clause": true` 时）允许跨段落放置 commentRangeStart 和 commentRangeEnd（Start 所在段落必须在 End 所在段落之前）；单处修订批注仍锚定在同一段落内
  （同一条批注的 Start 和 End 必须在同一段落内）
- **禁止**一条批注的 range 覆盖多个不相关的修订
  （如果两个修订属于不同的修改意图，应该用两条批注）
- **禁止**使用重复的 w:id
- **禁止**批注文本含 emoji；**禁止**用 `｜` 或空格冒充三段分隔（必须真换行）

## 7. comments.xml 结构

每条批注在 word/comments.xml 中对应一个 w:comment 元素；三段文本用多个 w:r（每段一个 run，段间用 w:br）表达：

```xml
<w:comment w:id="1001" w:author="AI审核" w:date="2026-01-01T00:00:00Z" w:initials="AI">
  <w:p>
    <w:r><w:t>【修改】未按法定指定媒介发布公告，应改按法定指定媒介发布并同步电子平台</w:t></w:r>
    <w:r><w:br/><w:t>【修订依据】依据《中华人民共和国招标投标法》第十六条……</w:t></w:r>
    <w:r><w:br/><w:t>【修订建议】修改为："……"</w:t></w:r>
  </w:p>
</w:comment>
```

## 8. 验证清单

生成文档后，AI 智能体应自检（可用 `scripts/verify_revisions.py` 自动执行）：

- [ ] 每条批注的 commentRangeStart 是否在对应修订元素之前
- [ ] 每条批注的 commentRangeEnd 是否在对应修订元素之后
- [ ] 修改类批注的 range 是否同时覆盖了 del 和 ins
- [ ] 所有 w:id 是否全局唯一
- [ ] 批注文本是否三段式（【修改】问题+怎么办 / 【修订依据】人话转述 / 【修订建议】可执行文本）
- [ ] 三段之间是否用 w:br 真换行（抽查 comments.xml 中 `w:br` 数量 = 批注数 × 2）
- [ ] 批注文本是否含 article_id / 空括号 `（）` / emoji（应为 0）
- [ ] 是否有 commentRangeStart 被放在 ins/del 内部的情况

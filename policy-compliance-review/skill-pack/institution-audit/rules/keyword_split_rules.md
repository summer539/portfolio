# 关键词拆解与本地检索规则

本规则供制度审核技能将制度条款转换为可检索的法律问题。它借鉴“先还原法律关系、再围绕潜在冲突构造检索词”的思路，但针对当前技能内置法规库 `lawdb/law.db`、SQLite FTS5 trigram 和可追溯审核要求重新设计。

## 1. 检索目标

每个需要法律检索的规范单元至少完成：

1. 正向核验：寻找支持、要求或细化制度规定的现行法源；
2. 反向排雷：寻找禁止、限制、例外或规定相反程序的现行法源；
3. 适用性核验：确认主体、事项、地域、项目类型、时效和例外条件；
4. 责任核验：涉及期限、比例、金额、许可、处罚时，补查对应法律责任。

没有检索到冲突，不等于“可以不改”。证据不足时输出 `NEED_LIBRARY_SUPPLEMENT`。

## 2. 最小规范单元

### 2.1 拆分标准

按“一个主体的一项行为及其法律效果”拆分。一条制度内出现以下任一情形，必须继续拆分：

- 主体不同；
- 行为不同；
- 法律模态不同（应当/可以/不得等）；
- 条件、期限、金额、比例或法律后果不同；
- 同一项中同时包含授权和禁止；
- 同一项中同时包含程序规则和实体规则。

条款定位保留到最细层级，例如 `第八条第（十三）项`。不得将第（十三）项和第（十四）项合并为一个检索单元。

### 2.2 字段模型

每个最小规范单元抽取：

```yaml
定位: 第八条第（十三）项
业务领域: 招标投标
具体事项: 评标报告复核
主体: 采购代理机构
相对主体: 评标委员会
法律模态: 可以/应当/不得
行为: 要求复核并纠正
对象: 评审结论
条件范围: 发现异常情形
程序数值: null
例外但书: null
```

字段允许为空，但不得为了凑字段虚构内容。

## 3. 法律命题重写

将制度语言重写为简洁命题：

```text
主体 + 法律模态 + 行为 + 对象 + 条件/范围
```

同时生成潜在冲突假设：

- 制度赋权：查询是否存在禁止、权限限制、前置条件或法定主体；
- 制度设定义务：查询是否允许自主决定、是否不得强制、是否存在例外；
- 制度禁止：查询是否存在法定权利、许可条件或例外；
- 制度设置程序：查询法定主体、步骤、期限、备案/审批性质；
- 制度设置金额、比例、数量或期限：查询法定上限、下限、计算基准、起算点和法律责任。

每个规范单元生成 1—3 个冲突假设，避免无限扩展。

## 4. 检索词分层

### 4.1 锚点词

选择区分度高、法律文本中稳定的实体或事项，例如：

```text
招标代理机构
履约保证金
中标通知书
评标委员会
```

高频模态词（可以、应当、不得）不得单独作为首轮查询。

### 4.2 规则短语

使用法律文本可能采用的连续短语：

```text
履约保证金不得超过
中标通知书发出之日起三十日内
依法指定的媒介发布
```

### 4.3 冲突短语

围绕反向假设构造：

```text
不得为招标人指定代理机构
不得挪用投标保证金
不得订立背离合同实质性内容
```

### 4.4 程序和责任短语

涉及程序或违法后果时补查：

```text
投诉行政监督部门
退还投标保证金及银行同期存款利息
超过规定比例收取履约保证金
```

### 4.5 标题和文号定位

知道可能相关法规后，停止宽泛扩展，改用：

- 法规全称或标题关键词；
- 发文字号；
- 法规标题定位后读取相邻条文；
- `article_id` 精确回读。

## 5. 本地 FTS5 适配

当前 `articles_fts` 使用 trigram，`legal_lookup.py` 已内置 LIKE 兜底：**3 字以上走 FTS5 短语检索，2 字及以下自动改走 `content LIKE '%词%'` 全表子串匹配**（条文 1.5 万条量级毫秒级）。因此：

- 正文查询优先使用连续的 3—20 字短语（FTS 路径，相关性排序更好）；
- **两字词（如"工时"）可直接查询**，LIKE 兜底保证有结果；1 字词同样兜底但噪声大，尽量用 2 字以上；
- LIKE 兜底对 `%`、`_`、`\` 做了转义，只匹配字面字符；
- 不使用带空格的“主体 行为 对象”作为一个查询字符串，因为它可能被当作含空格的完整短语；应改成多个连续短语分别查询；
- `%`、括号、引号等不得直接拼入 FTS5 语法；由脚本转义为字面量；
- 长句零命中时逐步缩短，但保留核心对象和行为；
- 标题/文号检索使用结构化 `LIKE` 查询，不走正文 FTS。

示例：

```text
不推荐：招标人 选择 招标代理机构
推荐：自行选择招标代理机构
推荐：指定招标代理机构
推荐：不得为招标人指定
```

## 6. 动态漏斗流程

不强制机械执行固定轮数。按证据覆盖动态停止：

1. 精确规则短语；
2. 缩短为核心实体 + 行为的连续短语；
3. 反向冲突短语；
4. 同义词和法律标准用语扩展；
5. 法规标题/文号定位；
6. 相邻条文、例外条文和责任条文核验；
7. `article_id` 精确回读并记录。

若早期已找到直接且适用的高位阶法源，仍须至少完成一次反向或例外检索，但无需机械跑满全部层级。

## 7. 同义词扩展

同义词只用于扩大召回，不得直接认定法律等同：

| 制度用语 | 检索扩展词 |
|---|---|
| 采购单位、项目单位 | 招标人、采购人 |
| 代理公司 | 招标代理机构、采购代理机构 |
| 自主确定 | 自行选择、自行选取 |
| 统一安排 | 指定、统一确定、限定选择 |
| 报备 | 备案 |
| 审核 | 审查、核准、审批 |
| 可不 | 无需、可以不、不予 |

必须结合主体、强制性、权限来源和程序效果判断，不进行机械替换。

## 8. 数字规则

期限、比例、金额、数量必须与法律对象绑定检索：

```text
履约保证金不得超过
中标通知书发出之日起三十日内
合同签订后五日内退还投标保证金
```

不得单独查询 `10%`、`30日`、`5日`。数字表达同时尝试阿拉伯数字和中文数字，但最终依据以法条原文为准。

## 9. 候选筛选与效力核验

候选法条至少满足以下两项，且不得仅因同词出现而保留：

- 主体相同或为法定对应主体；
- 对象相同；
- 行为同向或反向；
- 明确规定权限、禁止、程序、期限、比例、例外或责任；
- 属于该事项的直接上位法或配套规章。

最终依据必须核验：法规名称、文号、层级、状态、公布/施行日期、适用范围、具体条文、是否存在新版本或废止决定。

- `现行有效`：可作为最终依据；
- `已修改`：须确认数据库所存文本是否为当前版本；
- `已废止`：仅作沿革或说明，不得作为当前“必须改”的直接依据；
- `尚未生效`：不得作为当前已生效义务依据。

## 10. 查询日志（强制）

每个规范单元记录实际执行过的查询，不得只记录计划关键词：

```yaml
定位: 第八条第（六）项
规范命题: 采购代理机构可以自行选择公告发布媒介
冲突假设:
  - 依法必须招标项目的公告只能在指定媒介发布
实际查询:
  - query: 招标公告媒介
    mode: body
    count: 3
    article_ids: [2488, 2580]
  - query: 指定媒介发布
    mode: body
    count: 2
    article_ids: [2488, 2580]
候选淘汰: []
最终依据: [2488, 2580]
```

查询日志用于回答“实际搜了什么”，并支持后续复核和修订技能追溯。

## 11. 停止条件

同时满足以下条件方可停止：

- 已找到直接法源，或明确记录本地库证据不足；
- 至少执行一次反向冲突或例外检索；
- 已核验适用主体、事项和效力状态；
- 涉及数字/程序时已核验起算点、上限/下限和责任规则；
- “必须改”有现行有效直接依据和可执行修改建议；
- “可以不改”有正向依据或经过充分的适用性核验，不是因为零命中；
- 证据不足时输出 `NEED_LIBRARY_SUPPLEMENT` 并列出待补法规/内部制度。

## 13. 禁止事项

- 不把整段制度原文直接作为唯一查询；
- 不只做相似文本召回；
- 不只搜支持条款，不搜禁止、限制和例外；
- 不把零命中视为合法；
- 不引用未实际检索到的 `article_id`；
- 不使用已废止法条作为当前强制依据；
- 不把法规标题或搜索摘要当作具体条文；
- 不因关键词相同就认定适用；
- 不隐瞒实际查询词、零命中或待补库状态；
- 本技能默认只检索本地法规库，不自动调用外部商业数据库。外部检索和补库须单独启动并回到官方文本核验。

# 功能需求拆解概览

> 客户为某通信基础设施央企，项目信息已脱敏处理。

## 说明

项目启动阶段参与跨团队拆解客户需求，把客户的制度管理诉求拆成可评估、可排期、可验收的功能点，输出需求清单（V2.0）。清单按「序号 → 一级功能 → 二级功能 → 需求详细描述 → 需要客户提供的数据/说明 → 对应产品 → 产品侧能力评估 → 现存问题与待确认事项 → 技术路线 → 定制化工时」的结构组织，用于与客户逐条确认边界。

下面只保留功能模块结构，客户原文细节、内部能力评估与工时估算不在公开范围内。

## 拆解过程中沉淀的判定问题

清单里「现存问题与待确认事项」一栏累计提出了数十条需要客户或研发确认的问题，比较有代表性的几类：

- 范围边界：审核依据里的「法律法规、上级政策」是否等同于国家法律法规、党内法规、国资委监管要求、上级主管部门规定，需明确范围。
- 判断标准：法规被修改/废止的判定标准是什么，「同级制度」「类似条款」如何界定。
- 触发方式：一致性/冲突检测是主动比对还是全量扫描，是新增制度时触发还是定期触发。
- 呈现形式：审核结论是标注在制度原文中，还是以清单形式单独输出。
- 集成方式：制度系统、OA、4A 的对接边界与用户体系打通方式。

这些问题直接决定了后续 Demo 的功能取舍。

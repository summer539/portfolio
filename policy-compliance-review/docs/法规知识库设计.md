# 法规知识库设计

> 客户为某通信基础设施央企，项目信息已脱敏处理。

## 要解决的问题

首版 Demo 的瓶颈在外部法规：审核一份制度要反复翻法规原文、人工确认条款是否仍然有效，单份文件耗时长，结论也难复现。解法是把「每次现查」变成「本地可检索、效力状态可追溯」的底座。

## 库的规模

| 指标 | 数值 |
| --- | --- |
| 法规数量 | 3,837 部 |
| 条款数量 | 约 10.4 万条 |
| 效力位阶 | 法律、行政法规、部门规章、地方性法规、地方政府规章、司法解释、规范性文件、党内法规、香港法规 |
| 效力状态 | 现行有效 2,719；已废止 443；已修改 403；待确认 266；尚未生效 6 |
| 数据来源 | 国家法律法规数据库、国家规章库、官方网站、交易所披露、用户提供的法规文本 |

## 元数据字段

| 字段 | 说明 |
| --- | --- |
| `name` / `doc_no` | 法规名称、发布文号 |
| `level` | 效力位阶 |
| `issuing_org` | 制定机关，用于按机关分类树筛选 |
| `publish_date` / `effective_date` / `amend_date` | 公布日期、施行日期、最近修订日期 |
| `status` | 效力状态（现行有效／已修改／已废止／尚未生效／待确认） |
| `source` / `official_url` | 数据来源与官方原文链接，保证审核依据可追溯 |
| `preamble` | 法规前言，含历次修订说明 |
| `chapters[].articles[]` | 章节与条款结构，条款级正文（条号、所属章、内容） |

## 历史版本与效力处理

同一部法规的历次版本在库中以多条记录并存，用 `doc_no`、`publish_date`、`status` 区分。例如《中华人民共和国劳动法》：

| 文号 | 公布日期 | 状态 |
| --- | --- | --- |
| 主席令第 28 号 | 1994-07-05 | 已修改 |
| 主席令第 24 号 | 2018-12-29 | 现行有效 |

这样处理有两个作用：审核命中条款时能落到对应的现行版本；需要解释「这条为什么被改过」时，历史版本和修订前言可以直接作为依据，失效性核验不必依赖外部检索。

## 检索层

- 用 SQLite FTS5 建立本地全文索引，法规按条款切分后建索引，避免整篇匹配带来的误报。
- 支持两种检索模式：按法规标题检索、按条文内容检索。
- 支持效力位阶、制定机关、效力状态三类条件的组合筛选。
- 检索结果是条款级命中，直接带出处（法规名称 + 条号 + 原文），并可回链官方原文。

## 演示

`../law-database-preview/index.html` 是检索界面的离线演示版，浏览器直接打开即可检索、筛选和查看条款原文。为控制文件体积，演示版只收录了 24 部示例法规。

## 未纳入仓库的部分

完整库的预览文件约 56 MB，未上传：一是超出仓库体积的合理范围，二是法规正文属于公开信息、可重新采集。按上面的字段结构即可重建。
